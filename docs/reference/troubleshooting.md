# 故障排查手册（Troubleshooting）

遇到任何异常时，第一步先在主机运行内置诊断工具：

```bash
tycho doctor
```

它会逐项检查安装完整性、节点、执行器、账本、门牌、备份与自启定义，并直接给出「怎么办」建议。若仅需修复升级或挪目录后过期的启动器与自启定义，可运行：

```bash
tycho doctor --fix
```

---

## 一、安装与启动问题

| 现象 | 常见原因 | 解决方案 |
| --- | --- | --- |
| 终端提示找不到 `tycho` | 安装后未重开终端，或设置了 `TYCHO_NO_MODIFY_PATH` | 重开终端；或运行 `tycho doctor` 检查 PATH 项，直接调用 `~/.tycho/app/bin/tycho` |
| 启动报错「端口 8787 已被占用」 | 本机其他进程占用了默认端口 | 临时改端口启动：`tycho run --port 8788`；登录后在 **「设置 › 服务」** 永久修改端口 |
| 提示「数据目录正被进程 … 占着」 | 另一份 Tycho 服务已在运行，或正在做启动核实/恢复 | 先运行 `tycho status` 核对；确认要重启时用 `tycho stop`，**不要手工删除锁文件** |
| 提示「账本比程序新，请升级程序」 | 该数据目录曾被更新版本的 Tycho 打开过 | 运行 `tycho update` 升级到最新程序版本 |
| 桌面客户端点「连接本机」连不上 | 主机未启动，或主机修改了默认端口 `8787` | 先在主机确认 `tycho status` 显示运行中与实际端口，在桌面启动器填入对应 `http://127.0.0.1:<端口>` |

## 二、执行器与账号问题

| 现象 | 常见原因 | 解决方案 |
| --- | --- | --- |
| 负责人停摆 / 找不到 `claude` 或 `codex` | 主机未安装该 CLI，或后台自启服务记录的 PATH 里不含该目录 | 在能找到该 CLI 的终端重新执行 `tycho service install && tycho stop && tycho service start`；或在 **「设置 › 负责人」** 填写完整可执行路径并重启负责人 |
| 账号显示「已失效，要重新登录 / 重新填」 | OAuth 令牌或 API Key 过期/作废（系统不会自动重试） | 在 **「账号」** 页点击重新登录或更换 API Key；保存后排队任务自动继续 |
| 任务显示「等额度恢复，约 …」 | 该账号命中限流或额度用尽，进入自动歇息期 | 无需干预，系统会自动切换同项目其他账号或在重置时刻恢复；想提前重试可在账号页点 **「现在就试」** |
| 收到「账号 … 没有可用的机器」 | 该账号授权的在线机器均未安装该执行器或已离线 | 检查目标机器 `tycho node status`，确认在线并已安装对应 CLI |

## 三、节点、远程访问与升级问题

| 现象 | 常见原因 | 解决方案 |
| --- | --- | --- |
| 任务显示「执行机器失联」 | 节点与主机心跳中断 | 若属临时断网可等待恢复；超过宽限期（默认 10 分钟，可在「设置 › 执行」调整）后任务会自动在其他可用机器接续 |
| 公网门牌连不上 / SSH 报 `Permissions are too open` | 门牌私钥文件权限过宽，或公网 `sshd_config` / `authorized_keys` 限制不匹配 | Linux/macOS 执行 `chmod 600 <私钥>`；Windows 执行 `icacls "<私钥>" /inheritance:r /grant:r "$env:USERNAME:R"`，再运行 `tycho doctor` 核对 |
| 误改门牌或对外地址导致外网被锁在外面 | `http.publicUrl` 或 `gateway.ssh` 填错 | 登录主机终端运行 `tycho open --print` 取本机回环链接（无浏览器时走 SSH 本地端口转发），登录后改回即可 |
| 升级后提示「已退回上一版」 | 新版本未通过 10 秒健康检查，已自动回退且账本未动 | 查看 `<TYCHO_DATA>/service.log` 或 `journalctl --user -u tycho` 中的具体报错 |
| 节点版本落后于主机 | 节点当前有在跑轮次，或拉取升级包时网络异常 | 在 **「机器」** 页查看该节点的换版状态；空闲后会自动重跑，也可直接在该机运行 `tycho update --from <包>` |
