# 微信私聊接入

主人通过手机微信里的 ClawBot 与项目总控对话。Tycho 直接适配腾讯官方 iLink 协议，复用项目前台、项目总控、任务账本和 Outbox。服务端保持零运行时依赖。飞书真实群聊验收按主人 2026-11-14 的决定暂缓。

## 使用

在 Tycho 控制台以主人身份打开「设置 → 微信」，点「连接微信」。用手机微信扫码并确认。手机要求验证码时，在该页面输入手机显示的数字。页面显示已连接及微信身份即为连接完成。平台资格、手机版本或风控限制以微信实际提示为准。

在 ClawBot 私聊发送「我想换个项目」，从最新回复的列表中回复本页序号。项目超过八个时按页选择。普通对话不重复发菜单；主动发送普通项目消息会关闭尚未使用的数字选择，菜单十五分钟后也失效，之后的数字属于普通聊天。选择后可发「固定当前项目」，换绑先发「解绑」再重新选择。项目改名不影响已经保存的绑定，归档后可重新选择其他项目。

首次没有当前项目的要求先入账、等待选择。选择该条消息所属项目后，原文才交给总控。总控的最终回复回到原微信身份。系统事件按已有通知规则发送，正文保留原项目标识。控制台链接需要服务已有的对外地址；微信收发自身只需出站 HTTPS，无须新增公网回调端口。

此版接收文字私聊。图片、语音和文件收到明确的文字提示，不会把混合消息里的残缺文字当成完整要求执行。群聊、绑定他人的 ClawBot 和附件处理不在此次交付范围。

## 身份与恢复

每套服务连接一份微信身份，仅扫码确认的主人可指挥。微信与企微有独立白名单、消息去重和项目前台命名空间。项目绑定依据固定 bot ID 和用户 ID；切换账号后，旧账号的待发消息不能发给新账号，也不能改新账号的菜单。

`<数据目录>/secrets/weixin.json` 由运行服务的用户独占读取。它保存凭据、私聊 context token、不透明游标、尚未入账的消息及发送状态。二维码和 PIN 只留在登录内存中，二维码只由主人登录接口返回。一般状态接口不返回二维码，凭据不进账本、审计或日志。普通账本备份不包含该密钥文件，恢复到另一台服务后需重新扫码。

每批原始消息和新游标先在同一次原子文件替换中保存，再按稳定 bot、用户、消息编号入账。确认完整入账后才移除原消息。启动先处理本机待入账批次，再接受下一批。菜单翻页与该事件应显示的正文同时保存，崩溃重放不再推进一页。文字请求的项目选择、原文、待归属消息放行和回复在同一账本事务内完成。

发送前先保存意图。收到明确成功才保存已发送；超时、断线、非完整响应或发送成功后的本机记录失败都按未确认处理，不盲目重发。相同 Outbox 消息的固定分块编号及结果跨重启、断开和重新扫码保留。主人可在 Outbox 查看失败原因，先到原微信聊天核对，确需重做时重新发请求。断开会清除登录及会话上下文，保留无凭据的发送结果摘要。

回程依赖微信入站的 `context_token`。腾讯未承诺其永久有效期或任意离线主动发送能力。没有上下文时保留待发状态，提示主人先私聊机器人。明确登录失效会显示重新扫码，旧的在途轮询不能把已失效身份改回已连接。恢复记录不能写入或已损坏时停止收发并说明原因，保留现场。

## 协议依据与路线

采用薄协议适配。腾讯插件的发布包没有独立 SDK 接口，运行时依赖 OpenClaw 宿主。直接加载它会额外引入一套会话与执行框架，而 Tycho 已拥有这些责任。协议采用官方第三方版本后缀约定。

依据为 [腾讯协议说明](https://github.com/Tencent/openclaw-weixin/blob/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e/docs/protocol.md)、[官方发送实现](https://github.com/Tencent/openclaw-weixin/blob/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e/src/messaging/send.ts)、[官方账号实现](https://github.com/Tencent/openclaw-weixin/blob/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e/src/auth/accounts.ts) 与 [OpenClaw 微信渠道](https://docs.openclaw.ai/channels/wechat)。独立审查核对了官方 2.4.10 发布包和主仓。协议请求构造为自行实现，未捆绑第三方插件源码。

验收以真实手机扫码、文字收发、选择与解绑、连续普通聊天、任务结果回程和服务重启恢复为准。合成 API、真实账本故障注入、权限测试和页面测试支持这些验收，不能代替手机实际收发。

2026-11-14 已用真实手机扫码并在本机微信 Miro 私聊验收安装版 0.1.711。三轮普通聊天不重复项目菜单；固定验收辅助3后可在原聊天解绑，再从最新列表选择验收乙并重新固定。服务干净重启后，下一条消息仍交给验收乙总控，实际回复回到同一聊天。此前的真实建任务、Windows Worker 执行、报告读取、待验收回程和主人验收也已走通。此结论只覆盖上述文字私聊和实际账号，不扩展为群聊、附件或任意账号资格的保证。完整范围及发布边界见 [终态验收记录](terminal-architecture.md#82-已有证据和下一道门)。
