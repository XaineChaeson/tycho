# 控制台的设计

读者：改控制台页面的人（含 Agent）。回答的问题：一个新页面或一处改动该放在哪里、长什么样、用哪些现成的件。技术约束（React + TypeScript + Vite + Tailwind + Radix + TanStack Query，运行时不从网上取资源，服务端不 import 控制台）见 AGENTS.md，这里不重复。

## 一句话

主人打开控制台是为了三件事：处理等他的事、和某个项目的总控说话、看一项工作做到哪了。配置是偶尔才做的事。所以打开就是“总览”（等你的事排最前，能当场处理），项目是侧栏里的一级入口，配置收在侧栏下半部分。界面安静而紧凑：一个主色（钴蓝）给主操作和当前位置，**状态色只表达状态**，其余是带一点冷调的中性色。

## 页面与地址

| 位置 | 地址 | 放什么 |
|---|---|---|
| 总览 | `/` | 等主人处理的事（问题、待验收、停住的任务、没有机器的登录、待归属的消息），当场能答能验收；旁边是正在进行和刚结束；下面是派发、备份、建议配置、发送失败。 |
| 工作 | `/work`、`/work?show=ended` | 所有项目的工作。“在办”按等你 / 在推进 / 待验收分组；“已结束”分页，可按标题、编号、项目找。 |
| 用量 | `/usage` | 各登录还剩多少额度（能刷新），和每轮、总控每回合用掉了多少：按项目、模型、职能、档位、账号分，每日柱状图加明细表（docs/design/usage.md）。 |
| 项目列表 | `/projects` | 在用的项目，新建项目；已归档的收在底部一个默认折叠的“已归档”区。 |
| 项目 | `/projects/:id`、`…/work`、`…/triggers`、`…/settings` | 一个项目四个标签：对话（默认，宽屏右侧带这个项目在办的工作）、工作、触发器、设置。 |
| 工作、任务 | `/work/:id`、`/task/:id` | 有子任务的工作列出子任务；没有子任务的工作就是它那个任务的页面。任务页：要主人处理的在最上面，下面是每一轮的现场，右栏是任务的事实。合并卡片上，回执里带 PR 的那一轮不给“并入”，给 PR 链接：进主线要合 PR。 |
| 旧全局记录 | `/legacy` | 只读。 |
| 配置 | `/knowledge`（及 `/knowledge/proposals/:id`、`/knowledge/entries/:id`）、`/roles`、`/accounts`、`/machines`、`/inbound`、`/settings/:place?` | 侧栏“配置”组。`/inbound` 是整个 tycho 的入站来源，不在项目卡片里（docs/design/triggers.md §2.2、§7）。 |

服务端发出去的链接（企微卡片、自检的“去处理”、总控工具的回答）只用这些地址：`/task/:id`、`/work/:id`、`/projects/:id`、`/knowledge/proposals/:id`、`/settings/:place`、`/machines`、`/accounts`、`/inbound`。改地址要同时改 `service/doctor.ts`、`service/tools.ts`、`service/notify.ts`、`shared/labels.ts`、`channels/wecom-cards.ts` 里写死的路径。

侧栏从上到下：品牌和版本、搜索（Ctrl K，去任何页面、项目、在办的工作）、总览（带等你的件数）、工作、用量、项目列表（有事等你的带琥珀点和件数，在推进的带蓝点）、配置、运行状况（一切正常时一行，有问题时展开成每个部件一行）、放行、设备、深浅色。窄屏上侧栏是抽屉，打开它的按钮在页面自己的顶栏里。

任务页另有「任务反馈」和「回放与隔离重跑」折叠区。反馈可标记值得复用、太慢或结论错误，绑定任务修订和可选来源轮次；总控可经 `get_task` 读取。标记不会启动新任务或直接发布知识。录制事件回放、冻结规则评测与真实现场分开展示，具体用法见 [回放与评测](replay.md)。

任务「汇报」中的文件报告和「最后回复」共用报告抽屉，点击后才读取正文。抽屉标明来自执行节点、登记副本、结算保存还是历史原输出恢复；超过 128 KiB 的最后回复明确提示只保存了前段。旧轮次未保存正文时，仍提供入口尝试恢复，无法恢复则说明原因并允许重读。诊断事件过期不影响已经正式保存的最后回复。只读轮次的交付约定和保存边界见 [职能与只读](roles-and-tiers.md#5-权限)。

「设置 → 执行」控制每轮诊断事件数量、总字节预算及单段工具输出上限；「设置 → 保留」控制正文清理期限。说明必须区分诊断正文与账本回执、摘要和状态，不承诺已裁剪正文可恢复。发送结果未确认时，总览允许主人在原聊天核对后「已确认收到」；这只确认通知，不重发，也不验收任务。

## 视觉语言

所有颜色、字号、圆角、阴影、断点都在 `console/src/index.css` 里声明一次，页面只用 Tailwind 的语义名，不写色值、不写任意像素字号。

- **颜色**。中性色分四层底（`canvas` 窗口、`background` 页面、`raised` 卡片和浮层、`muted` 安静的填充；`hover` 是指针下的填充）和三档文字（`foreground` 读的、`muted-foreground` 解释的、`faint` 只做标签的）。主色是钴蓝（`primary`，浅底用 `brand-soft`/`brand-foreground`）：主按钮、当前位置、被选中的选项、焦点、链接。状态色全站同义：蓝 `running` 在跑，琥珀 `waiting` 等主人，红 `failed` 出错，绿 `success` 通过或正常，灰 `ended` 结束；每种有四个值：标记本身、浅底上的文字（`-foreground`）、浅底（`-soft`）、浅底的边（`-border`）。颜色从不单独承担信息，旁边总有字。浅色和深色是同一组变量的两个值（`light-dark()`）。
- **文字**。拉丁字母和数字用 Inter，中文用 Noto Sans SC，等宽用 JetBrains Mono，三种都随包带（中文按字切片，页面只加载用到的片），所以每台机器画出来一样。正文 `text-sm`（13px）到 `text-base`（14px），标签 `text-xs`（12px），对话和 Markdown 正文 `text-base`、行高更松；页内大标题 `text-2xl`。强调用 `font-semibold`，`font-medium` 只用在导航当前项、按钮这类有底色配合的地方。
- **表面**。窗口底色带一点主色的渐变，页面是它上面一块带柔和阴影的圆角面板。卡片和列表不画粗边框，用一像素的环加很轻的多层阴影（`shadow-card`）。同类对象用一个圆角容器加行间分隔线（`Rows`），不要一个对象一张大卡片；确实要成组的用 `Card`，卡片不套卡片，卡片里再分组用分隔线或小标题。要主人处理的卡片用琥珀色的边和页眉。
- **状态的记号**。任务的状态用形状各不相同的小图标（`StatusDot`：转动的弧是在跑，圆环加点是排队，问号是等你，实心环是待验收，暂停是停住，对勾是完成），颜色随状态；项目有按名字算出色相的标识（`ProjectMark`）。
- **图表**。系列色是 `series-1` 到 `series-5`（按这个顺序给用得最多的几组，其余合成灰色的“其他”），只表达“是哪一组”，从不表达状态；颜色旁边总有图例文字，图下总有同样内容的表。柱子从零起、一根轴，悬停说出这一天每组的数。
- **控件**。高度是 `--hit`（鼠标 32px，触屏 44px）。一处只有一个实心主按钮（`primary`，上亮下暗）；其余是描边的 `secondary`；行内和工具栏里的动作用 `ghost`；不可撤销的用 `danger`，到了确认那一步才是实心的 `danger-solid`。
- **动效**。只有浮层出现、抽屉滑入、悬停变色，都在 0.2 秒内；`prefers-reduced-motion` 时全部关掉。

缺什么加在这些文件里，不在页面里另起一套样式。

## 做法

- **列表加抽屉。** 配置页是一个列表（或几张卡片）加一个抽屉：列表只读、紧凑，说清每个对象现在怎样；“修改”“新建”在右侧抽屉里做，保存和取消固定在抽屉底部。页面不因为打开表单而跳动。
- **整页表单用保存条。** 一页就是一个对象的设置时（项目设置），字段一直可改，改过才在页脚出现“有改动还没保存 · 取消 · 保存”。立刻生效的动作不放进草稿表单：项目最上面是名字（跟着保存走）；暂停和归档各自单独一节，一个按钮加状态标记，说明里写“立刻生效”；项目的常驻规则是知识条目，单独一节用列表加抽屉，排在保存条管的那几节之后；项目的“总控可以自己做”是保存条管的一节，一步一个开关，开关下面一行写这一步做什么、前提是什么。暂停的项目在它每个标签页的顶栏下面有一条 `Callout`（带“恢复”），项目列表用 `Badge` 写“已暂停”，侧栏的项目名变灰加暂停小图标；归档的项目标题旁写“已归档”，对话的输入框位置换成一条“项目已归档”的说明（`PROJECT_ARCHIVED_NOTE`）和“恢复”；侧栏、命令面板和首页/工作列表/任务页的项目选择器都不列它（知识作用域的项目勾选仍列已归档项目：归档项目的知识还要能管理），项目列表底部折起“已归档（n）”。删除是设置页最下面的危险样式一节：空项目或已归档且没有在跑轮次的项目给按钮，确认框要求把项目名打全、按钮才可点，并列出服务端给的会删计数和会保留的东西；有历史还没归档时只写“先归档才能删除”，不给按钮。壳子顶部的横幅只给服务自己的问题用。
- **删除、放弃、吊销先问。** 用 `Confirm`，按钮上写清要做的事（“确认删除 X”）；服务端说“要确认才做”的（`needs_confirm`），把它给的代价原话显示在确认框里，再点一次才带上确认发出去。
- **失败说在发生的地方。** 表单的拒绝写在表单里（`role="alert"`），不清空已填的内容；没有固定位置的动作失败用 `live.showError`，它在页面底部浮出一条，换页即清。
- **说明文字跟着它说明的东西。** 页首只有一句“这页是做什么的”；规则细节写在字段下面的小灰字里或折叠起来，不在页面上堆段落。
- **读和写。** 数据只经 `lib/queries.ts` 和 `lib/api.ts`；页面不存服务端状态的副本，改完用回答更新缓存或让查询重读（`useChange`）。读不到的如实说，不显示旧值冒充新值。
- **加账号只有一个入口。** 账号页的“添加账号”打开一个窗口：先选执行器，再选怎么登录（在官方页面授权、填 API 密钥、选线路填密钥、在一台机器上登录，各执行器声明哪几种就画哪几种），后面的步骤都在这个窗口里走完。不问名字：服务按登录的身份给新账号起名，要改到账号的抽屉里改。能由系统得出的东西不让人填。执行器能不能当账号、能怎样登录是它自己声明的，窗口照着画；不能当账号的执行器也列出来，写明它的登录在机器上（docs/design/native-login.md 文末）。同一件事不给两个并列的入口。
- **账号页列两类登录。** 上面是 tycho 保管的账号；下面一节是机器上已经登录好的执行器——机器报告已登录就自动有一份，带适配器声明的默认档位，不用主人登记。每行用机器页同一个表单（`LoginEditor onMachine`）和同一组接口改档位、权限模式和限制，能删除，额度歇着时“现在就试”；状态用机器页同一处判定。点“添加账号”只造账号那份登录；在一台机器上登录完成时，表单从那台机器这个执行器现有的登录读初值。
- **能列出来的就给选项，不让人手填。** 档位里的模型从这份登录的执行器报告的列表里选：账号的列表由服务带令牌去问，机器自己的登录由那台机器报告（docs/design/nodes.md §1.2），两处是同一个表单、同一个下拉。读到了列表，空着的档位先给的就是下拉；“手填模型名…”是下拉里的一项，给列表里没有的别名用。没读到列表才退成手填的框，并在档位上方写明为什么没读到。
- **登录。** 账号抽屉可以改名，保存始终按内部编号更新；项目和设置也存登录编号、显示当前名字。登录的完整称呼只经 `shared/logins.ts`，机器自己的登录显示为“机器 M 上的 E 登录”；轮次历史显示启动时的名字。
- **窄屏。** 每个页面在 375px 宽时不横向滚动；第二栏在 `wide` 以下折到正文下面或收进折叠。
- **文字。** 界面文字用中文大白话、用主人的词；执行器、档位、职能的叫法只从 `shared/` 读。

## 数据怎么保持新

答案：页面不自己定时去问，等服务说“变了”再重读在屏的东西；重读时旧内容留在原处，只有第一次读才显示骨架。

- **一个信号。** 账本每提交一个带审计记录的事务（或写了页面要显示、而且确实变了的学到的状态：登录的额度数字和歇息、模型清单、用量），服务在一个操作结束后在事件流上发一条不带内容的 `changed`；额度读取结束（不论读到没有）、总控停摆和重启结束也发。控制台在 `lib/live.ts` 一处收它，攒 100 毫秒，然后让所有在屏的查询重读、不在屏的标成过期（下次显示时重读）。页面和别的代码不另发重读，也不另开刷新机制。机器每次连回来写的“上次听到”、一轮的进度这类频繁的学到的状态不发，否则每个打开的控制台都会被叫醒。
- **15 秒的钟只兜账本以外的东西**：机器连着没有、自检、服务自己的状态、设置页上总控此刻的状态、任务为什么在排队（看此刻连着哪些机器）、项目代码目录在哪个分支（读磁盘）、总览上一轮正在做什么、放行请求、控制台会话、触发器的拒收计数（不写审计）。其余查询没有 `refetchInterval`。登录窗口自己的 1 秒轮询是那次登录会话的状态，不算在内。
- **重读不清空。** 查询重读时页面照旧显示上次的答复，回来后原地换上；骨架（`components/ui/skeleton`）只在第一次读、还什么都没有时出现，并占住它要替换的内容的高度。
- **换对象不露出别的对象。** 对话按“项目 + 段”各留一份：回到读过的那段，先显示上次读到的，后台再读，读回来的整份替换它；没读过的显示骨架，绝不在乙项目的标题下露出甲项目的消息或总览时读到的消息。项目的排队消息有了第一段，还是同一段对话，不闪骨架。一段对话和每个请求提交了什么是同一次读取（`/api/messages` 的 `changes`），不按回合一条条问。
- **不会再变的就不再读。** 已经结束、输出读全了的一轮（不是失联判定结束的，也不是机器失联或被移除后按停止意图结算的）记录不会再变：它的事件和快照留在缓存里（`meta.lasting`，`changed` 不让它重读），控制台开着的 30 分钟内再打开任务页时在第一次绘制里就有。

## 测试

页面测试（`*.test.tsx`）在替身服务上开整个控制台（`src/test/harness.tsx`），按可访问的角色和名字找元素，断言发出的请求和页面上的结果，不看类名和内部结构。改布局时能力不变，测试跟着新的名字和步骤走；删掉一条断言要有“这个能力不在了”的理由。浏览器冒烟在 `console/e2e/`。
