# 在 tycho 里登录自己的账号

定稿，主人 2026-11-10 确认照此分步实现。读者：主人和实现者。文中的"你"是主人。
来源：两份独立设计稿（dsh 决策档、Codex 决策档）互审后，由总控裁决合成。第二节里"dsh 的 provider 当账号"是你在互审派出之后提的，没经过互审，单独标明。

## 一、结论

**Claude 和 dsh 能做到"登一次，放行过的机器都能用"；Codex 做不到，它的登录跟着机器（或跟着共享的 Home）走。**

| | 你怎么登 | 登录放在哪 | 哪些机器能用 | 多久要重登 |
|---|---|---|---|---|
| Claude | 在账号页点登录，跳到 Claude 官方授权页，把授权码贴回来 | tycho 保管 | 项目放行的每台机器 | 约一年，到期前 30 天提醒 |
| dsh | 在账号页填一条 provider 线路和它的密钥 | tycho 保管 | 项目放行的每台机器（要够得着那个地址） | 密钥不过期就不用 |
| Codex | 在账号页选一台机器，跳到 OpenAI 页面输入用户码 | 那台机器的 Home 里，Codex 自己的目录 | 用这个 Home 的所有机器 | 厂商自己续，失效时提醒 |

Codex 的限制来自厂商：它的登录会定期轮换，同一份拷到多台机器会互相挤掉；厂商给外部程序集中续期的接口标着内部使用。所以 tycho 不复制它的凭据文件，只替你在那台机器上发起一次原生登录。

**你的集群实例共用 Home，所以在任意一台实例上登一次 Codex，所有实例都有了，包括以后新建的。** 这份登录挂在 Home 上，不挂在某台实例上。实例删掉、换成新的，登录和它的档位都还在，不用重登，也不用重填。

今天不是这样：机器自己的登录按"每台机器一份"记，每来一台新实例就多出几行要你填档位的登录。这次一并改掉。

主人确认了两件：整体照此做；接受 Codex 这条限制。

## 二、你会看到什么

### 账号页：一份清单

页面仍叫"账号"。你的全部登录列在同一页：tycho 保管的，和机器自己的。每一行写明执行器、名字、能在哪用、状态、档位。机器页上原来的登录入口跳到这里。

### Claude

1. 点"添加账号"，选 Claude，起个名字。
2. 弹出一个居中的窗口，显示"正在准备"，几秒后出现"前往 Claude 授权"按钮和一个输入框。
3. 点按钮，在你自己的浏览器里完成授权，把页面给的授权码贴回输入框。
4. 窗口显示"已登录"，接着让你填档位。

手机经门牌访问时流程一样。旧的"贴令牌"表单同时删除。

- 授权码不对时，点"重新授权"会换一个新的授权链接。一次尝试只换一次码。
- "重新登录"时，新令牌存好了才替换旧的；中途取消或失败，旧登录不变。
- 到期日写"预计到期"，按登录那天加一年估算。厂商不提供确切日期。

### dsh：一个账号就是一条 provider 线路加一把密钥（后加，未经互审）

1. 点"添加账号"，选 dsh，再选线路类型："DeepSeek 官方"或"自定义 provider"。
2. 官方线路只填密钥。自定义线路填名称、协议、地址、模型清单、密钥；重试、请求头、超时放在"高级"里。
3. 保存后填档位。档位表单只在这个账号的模型清单里选模型和强度，不再有 provider 一栏。

之后每一轮，tycho 自己生成 dsh 的配置并下发，密钥随启动环境给到那一轮。你不碰任何文件，机器上也不留密钥。改地址或模型清单不用重填密钥。

- 内网地址只有同网段的机器够得着。够不着时那一轮失败，原因写在任务上。
- 第 4 步之后，账号上有"在某台机器上测试连接"按钮，顺带读回模型清单。在那之前模型清单手填。
- 新建的账号显示"已保存，尚未用过"，第一轮跑通后才显示"可用"。

### Codex

1. 点"添加登录"，选 Codex，选一台在线的机器。窗口标题写明"登录 Codex 到 <机器名>"。
2. 窗口显示 OpenAI 的验证页按钮和一个用户码，可一键复制。
3. 你在 OpenAI 页面输入用户码并授权。窗口自动变成"已登录"，显示登录的身份。

这份登录就是那台机器上 Codex 命令行自己的登录。在 tycho 里重登，等于在那台机器上重登，窗口会先说明这一点。

- 这份登录上还有任务在跑时不能重登。页面列出是哪几轮，等它们结束再来。登录进行期间不往这份登录派新任务。
- 选哪台机器只决定在哪台上发起。登录成功后，页面显示的是"<Home 的名字> 上的 Codex，N 台机器在用"。
- 取消和授权成功可能同时发生。这时页面写"已取消，但这台机器现在已登录为 …"。

### 机器自己的登录

机器上原本就有的登录照旧列出，只读。它们都挂在 Home 上：共用 Home 的机器合成一行，一台机器独占 Home 时看起来和现在一样。用这个 Home 的机器暂时都不在线时，这一行留着，写"目前没有在线的机器"。
dsh 在机器上的登录保留，因为 DeepSeek 账号线路只能在那台机器上自己登（它的授权回调只认本机地址）。

dsh 没有命令能回答"登录了吗"，所以这一行写"登录状态问不到"，照常派活。被拒一次后停用，由你点"现在就试"恢复。

### 等待、失败、取消

- 一次登录最多等 15 分钟（可在设置里改）。关掉窗口等于取消。服务重启会中断正在进行的登录，重新点一次即可。
- 失败只显示固定的几类原因，例如"授权码未被接受""连接不上厂商""认不出这一版的登录结果""这台机器的系统策略拒绝了登录助手"。不显示厂商的原始输出。
- 在 tycho 里删除账号，只是 tycho 不再保管它。要让它在厂商那边失效，得去厂商的页面撤销。

## 三、分歧怎么裁的

两位审阅者意见一致的九条直接采纳。A、B、C、D、F、G、I、K、L 属于这一类。

| | 分歧 | 裁决 | 理由 |
|---|---|---|---|
| A | 页面叫"账号"还是"登录" | 叫"账号" | 设置页已有一个"登录"分组，讲的是浏览器会话 |
| B | dsh 机器登录删不删 | 保留，只读 | 删了 DeepSeek 账号线路就没有入口；今天的派发本来就允许它试跑 |
| C | 登录过程存不存账本 | 不存，只在内存 | 服务重启后登录进程本来就没了，存下来也续不上 |
| D | Claude 授权码被拒后 | 结束旧进程，取新链接 | 原型实测：原地重试也会换链接，保留它要多认一套屏幕状态 |
| E | 共用 Home 的机器 | 机器上报 Home 的标识，页面显示为同一份登录；不限制只许一台用 | 见下 |
| F | Codex 重登撞上在跑的轮次 | 拒绝并列出占用的轮次 | 排队等待要新造一套暂停和恢复，还会被登录时限截断 |
| G | 执行器输出里的密钥 | 写盘前隐去已知密钥，放在公共入口，不是 dsh 专用 | 输出会进账本和企业微信推送；Claude 那条路今天也没有这层 |
| H | dsh 密钥用哪个环境变量 | tycho 自己定 | provider 定义由 tycho 生成，变量名是它的一部分，不需要机器上报，也不需要你填 |
| I | 每轮记登录修订号 | 不记 | 找不到不记会坏的场景 |
| J | 设置项和默认时限 | 三项：登录时限 15 分钟、清理等待 10 秒、到期提醒 30 天 | 准备阶段共用登录时限；15 分钟是 tycho 的默认，不是厂商的规定 |
| K | 机器上的登录进度怎么回主机 | 复用现有长轮询，登录期间轮询间隔压到下限 | 另开专用接口等于两条路做一件事 |
| L | Claude 到期日 | 写"预计到期" | 厂商只说一年，不给确切日期 |

**E 的裁决两位审阅者相反，我取中间。** 一位要"只许一台机器登记使用这份登录"，另一位要"完全不处理"。只许一台，会砍掉你今天在集群上已经在用的能力；完全不处理，页面就会说假话（"每台各登一次"），F 的占用检查也只看得到一台。所以：机器上报 Home 的标识，机器自己的登录按 Home 记一份，不按机器记。共用的机器用的是同一份登录、同一套档位；重登时检查这几台上所有在跑的轮次。新实例接入后不需要对登录做任何事。多台同时续期会不会互相挤掉，现有材料证明不了，放进验收。挤掉了的表现是那份登录被标为失效、提醒你重登；真出现再加"一份共享登录同时只跑一轮"的限制。

## 四、实现要点

**对象与账本**

- dsh 账号多一份 provider 定义（不含密钥）。没有新表。
- 机器多一个 Home 标识：客户端第一次运行时在自己的数据目录里放一个随机标记，数据目录在 Home 下，共用 Home 的机器读到的是同一个。不往各家执行器的目录里写东西。
- 机器自己的登录从"每台机器、每个执行器一份"改成"每个 Home、每个执行器一份"，三家同一条规则。账本升一版，现有的行按机器上报的 Home 合并，档位取最近改过的那一份。
- 建账号时的凭据输入框、直接换令牌的接口删除，凭据只经登录流程进入。dsh 的"换密钥"是同一个流程。
- 适配器把“凭据怎么交给一轮”声明成一种：启动环境里的一个变量。依赖旧声明的地方一起改：`service/main.ts`、`cli/service-checks.ts`、测试辅助、`AGENTS.md` 里的规则。
- 托管的 dsh 账号，档位"高级"原文里不许再改凭据服务和 provider 定义。否则机器上的旧凭据文件会抢在托管密钥前面。

**机器客户端协议（4 升 5，只升一次）**

- 新增三条封闭命令：开始登录、取消登录、测试 provider 连接。
- 轮询请求里带上本机正在进行的登录清单。终态保留到主机确认收到。

**秘密**

- 登录进程的全部原始输出从启动起只在内存里，不写盘。
- 令牌保存前检查格式（现有存储只收 500 字以内、不含空白的一段）。不合格按"没取到"处理。
- Claude 命令行自己会尝试在主机上开浏览器，启动时要压住，并进验收。

**进程回收**

- 只按自己记下并核实过的 PID 加启动时刻结束进程。
- 登录助手监视与父进程的通道，并带着截止时刻；父进程消失或到点都自己收场，不等下次启动再清。
- 清理确认不了时保留证据，页面如实写"尚未确认结束"。

**登录助手（伪终端桥）**

- 只有 Claude 在 Windows 主机上登录时用到。C# 源码随包带，首次使用时编译，按源码哈希缓存；编译器不可用时退到 PowerShell。
- 启动授权前先跑一次不含秘密的自检。两条路都被系统策略拒绝时如实报告，不改策略。
- 不提供远程终端。

## 五、分步

每一步做完都能单独用。第 1 步的前半（做到真实登录能存下令牌，不改账本）和删 SSH 那一片并行做；其余排在那一片合入之后，因为它们要改账本和凭据交付。

| 步 | 交付 | 怎么算完成 |
|---|---|---|
| 1 | Claude 登录窗口（含居中窗口这个基础件、登录助手、预计到期与提醒），删贴令牌表单 | 你真实登录一次；同一个账号在两台机器各跑一轮 |
| 2 | dsh provider 账号（建账号表单、配置生成、环境交付、输出隐去、档位表单） | 你的内网线路在本机和一台集群实例各跑一轮；机器上不留密钥 |
| 3 | 账号页统一清单（机器登录并入、机器登录改为挂在 Home 上、dsh 机器登录的说明） | 每份登录的使用范围、状态、档位在一页看全；新实例接入后不出现要填档位的新行 |
| 4 | Codex 设备码登录、重登互斥、provider 测试连接 | 你用手机把 Codex 登到一台指定机器；取消、掉线不留进程 |

第 1、2 步互不依赖，可以并行。

Linux、macOS 主机上的 Claude 登录不排期：你的主机是 Windows，目前没有使用者。在那之前，非 Windows 主机上的 Claude 登录入口显示"此主机暂不支持"。

## 六、还没验证的，和怎么验

第一次真实登录由你本人操作。实现者只看归一化后的状态，不记录授权码、用户码、令牌和完整链接。

| 你做的操作 | 要看到什么 | 出现什么就得改设计 |
|---|---|---|
| Claude 完整登录一次 | 令牌完整取到并存好；进程全部收回 | 成功那一屏认不出来、令牌折行丢字、令牌超过存储限制 |
| Codex 登到机器 A | 成功通知和身份一致；重启客户端后仍能跑 | 登录写进了别处，和实际执行用的不是同一份 |
| 两台共用 Home 的实例同时跑 Codex，跨过一次续期 | 两边都正常 | 互相挤掉：加"共享登录同时只跑一轮"的限制 |
| dsh 自定义线路跑一轮 | 密钥从启动环境取到，凭据服务保持关闭 | 这条线路必须开凭据服务：改成每轮写一份隔离目录里的凭据文件 |
| 受限的 Windows 环境启动登录助手 | 两条路至少一条可用 | 都被拒：该环境不支持 Claude 登录，如实说明 |

"Claude 成功那一屏"是唯一可能推翻整条 Claude 路线的点，所以第 1 步分两半：前半做到登录窗口能真实登录并存下令牌，上线后请你验收；验收通过再做后半（删贴令牌表单和直接换令牌的接口、预计到期与提醒）。

## 七、要更正的两处文档

- `accounts-machines-decoupled.md`：Codex 登录"不能当成可搬运的凭据"，收窄为"不能把同一份会轮换的登录拷到多台机器并发续期"。
- `accounts-and-machines.md`：dsh"无人值守要打开三个服务"，只对存储式和账号式的线路成立；provider 密钥随启动环境传入时三个服务保持关闭。

第 3 步落地时，`nodes.md` 里"机器只报告事实"一段补上 Home 标识。同一份文档里"任务派生的临时机器只能用账号"也要改：派生出来的实例如果用的是已有的 Home，那个 Home 上的登录它同样能用（仍受名额里的项目和执行器限制）。这样 Codex 才能在派生的实例上跑。

## 八、相关但不在本稿：机器接入不该逐台放行

你指出实例是临时的，每台都当独立机器让你放行，噪音太大。这是机器接入的问题，不是登录的问题，另出一份设计稿。方向：

- 放行的单位从"一台机器"改成"一个环境"。你为一个环境（例如研究集群）建一次接入口令，放在这个环境的 Home 里；之后这个环境里的任何实例启动客户端就自己接入，不用你点放行。
- 项目放行的也是环境，不是逐台机器。实例下线一段时间后自动从清单里消失。
- 逐台输六位数放行只留给零散的机器，例如一台新笔记本。

本稿第 3 步"登录挂在 Home 上"不依赖那份设计，可以先做。

## 落地记录

### 第 1 步前半（Claude 登录窗口，2026-11-10）

做到了：控制台能发起真实的 Claude 登录并把令牌存进账号；贴令牌表单和直接换令牌的接口当时照旧保留，后来删掉了（见本文末“贴令牌的入口已删”）。没有改账本 schema。

**形状**

| 部分 | 在哪 | 做什么 |
|---|---|---|
| 登录助手 | `service/ptybridge.cs`（随发布包）、`service/ptybridge.ts` | ConPTY 里跑一条命令、原样转字节。首次使用时用系统的 csc 编译，按源码哈希放在 `<数据目录>/login-helper/<哈希>/`（找编译器、按哈希编译并缓存、并发下草稿改名落地这套机制和进程查询助手共用，只有 `service/csharp.ts` 一处；已有的程序直接复用，编不出来就走 PowerShell 那条路）；编译器不可用或编出来的程序跑不起来，退到 PowerShell Add-Type（脚本经 `-EncodedCommand` 传，不落文件）。每次登录前跑一次只回显的自检（`cmd /c echo` 加固定退出码）。两条都不行时登录失败，原因“这台机器的系统策略拒绝了登录助手”，服务日志写两条路各自的原话 |
| 助手怎么收场 | `ptybridge.cs` | 带着父进程 pid 和截止时刻启动：父进程消失、标准输入断开、到点，任何一种都自己退出；命令在“句柄关闭即结束”的作业对象里，助手一退出整棵树跟着结束 |
| 画面解析 | `service/login-screen.ts` | 去控制序列（光标右移换成空格）；网址先取 OSC 8 的目标；只从交码后的输出取令牌，认出的失败优先。令牌认 `sk-ant-` 开头、独占一行、折行接回；等候选后出现不可能续接的一行、进程退出，或候选行结束后画面稳定，才算整段。令牌旁边有别的字就不猜，算认不出；形状把每个字母换成 a、每个数字换成 0 |
| 登录会话 | `service/claude-login.ts` | 只在内存。状态：准备中 → 等授权码 → 交换中 → 已登录 / 失败 / 已取消；失败原因只有 `shared/claude-login.ts` 里那几类。一次尝试只交一次码；同一账号新开一次先取消旧的。每次登录一个 `<数据目录>/login-sessions/<编号>/`，CLI 的 HOME、APPDATA、`CLAUDE_CONFIG_DIR` 都在里面，结束时删除，启动时清掉崩溃留下的；`BROWSER` 指向那里一个不存在的程序，压住 CLI 自己开浏览器。结束进程只用自己起的句柄，残留的按记下的 pid 加启动时刻核对后再按 pid 结束；清理等待之内确认不了就写“尚未确认结束”，日志留 pid 和启动时刻 |
| 接口 | `service/http.ts` | `POST /api/claude-logins`（开始：新账号只发 `{ mode: 'new' }`，重新登录发 `{ account, mode: 'relogin' }`；新账号不读请求里的名字）、`GET /api/claude-logins/:id`、`POST …/:id/code`、`POST …/:id/save`（新账号的档位和限额；执行器和令牌是登录给的，页面传了就拒）、`POST …/:id/cancel`，全部 `outside: true`。`/api/accounts` 多一项 `claude_login`（这台主机能不能在这里登录；后来换成按执行器给出的 `account_logins`，见文末“账号页只有一个入口”） |

| 控制台 | `console/src/components/ui/dialog.tsx`、`console/src/components/claude-login.tsx`、账号页 | 居中窗口基础件（设备页的确认框也改用它，`role="alertdialog"`）；账号页的登录入口和每个 Claude 账号上的“重新登录”（入口后来并进“添加账号”，见文末“账号页只有一个入口”）；非 Windows 主机上不可用并写明“此主机暂不支持” |

**实现时定下的几处**

- 新账号的令牌拿到后先留在会话内存里，主人填完档位才经 `accounts.put` 建账号。原因：建账号那一处要求至少一个档位，不能为了先建号编一份档位；关窗口或超时，这次令牌作废，窗口上写明。拿到令牌后再给一个登录时限填档位。
- 重新登录拿到令牌就经 `setCredential` 换上，失败原因 `not_saved`，旧令牌不动。
- 准备、等码、交换共用一次登录时限。网址和粘贴提示都已观察到才收码，交换只用剩余时间；到期仍认不出结果时附形状。主人临近截止才交码、尚无新输出时，保留交码前已有画面的形状。
- 静默只能确认已经结束的候选行。ConPTY 隐藏光标时可能省掉末尾的换行；若没有后续内容、退出或可观察的行结束，证据不足，等到时限按认不出处理，不保存候选。
- 开始请求属于打开的窗口：关闭或卸载后，迟到的开始答复也立即取消服务端会话。新账号等填档位时继续轮询，暂存令牌到期后显示作废并给“重新授权”。
- 认不出时形状进服务日志，也进这次登录的回答（`shape`），控制台收在“这一屏的形状”里。

**测试**：`tests/login-screen.test.ts`、`tests/ptybridge.test.ts`、`tests/claude-login.test.ts`、`tests/claude-login-http.test.ts`、`tests/claude-login-service.test.ts`、`console/src/components/claude-login.test.tsx`、浏览器冒烟里一条走通假登录。都用 `tests/fake-claude-login.mjs`（按原型实录的画面行为），不碰真的 claude。依赖 ConPTY 的只在 Windows 上跑。

**还欠的验收（主人做）**：在 Windows 主机的控制台账号页，以主人身份点“添加账号”、选 Claude、选“在官方页面授权”，到官方页面授权并贴回授权码；窗口显示“已登录”后填档位保存，账号出现在清单、同一账号在两台机器各跑一轮即通过。另用“重新登录”走一次中途取消，原账号仍能跑；关掉开始请求尚未返回或正在交换的窗口后，会话应取消且进程核验完成。等填档位超过登录时限时，窗口应显示作废和“重新授权”。成功画面的令牌前缀、折行、长度和末行结束方式仍待真实验证；认不出时只提供失败详情里的形状，不提供授权码、令牌或网址查询部分。

### 登录后的模型与账号识别（2026-11-10）

新账号授权成功后，服务用暂存令牌自动读模型；登录窗口把结果交给修改账号时用的同一个档位表单。读不到就显示原因并允许手填。保存时，账号、初次模型清单和执行器身份事实一起提交，初次清单不发新增模型通知。重新登录不额外查询。

模型查询与定时刷新共用 `service/models.ts` 的 `readModels`。适配器声明成功的模型响应头中的组织标识；服务和表单只读归一化事实。组织与已有账号相同就显示账号名并说明属于同一个 Claude 组织，保存事务再次核对并拒绝另建；同一组织可能有多个账号。没有组织标识就写“认不出是哪个 Claude 账号”，不拦保存。（原来还有一个读邮箱的资料请求，2026-11-12 实测读不到，已删，见文末“Claude 登录令牌读不到账号是谁”。）

账本版本 25 在 `login_state` 加 `identity_json`，不改账号配置。旧账号从未知开始，下次模型刷新补组织标识。假 HTTP 服务器验证了组织头和坏回答的行为。真实模型回答带组织头（2026-11-12 两个账号实测都带）。

### 第 1 步后半：预计到期与提醒（2026-11-11）

做到了：账号的预计到期和到期提醒。贴令牌表单和直接换令牌的接口当时照旧保留，原计划等真实登录验收通过后删除，后来删掉了（见本文末“贴令牌的入口已删”）。

**形状**

| 部分 | 在哪 | 做什么 |
|---|---|---|
| 有效期 | 适配器声明（`credentialLifetimeDays`） | 执行器自己说它的令牌大约能用多少天；Claude 是 365 天。没声明的执行器没有预计到期，页面和提醒都不出现这一项。这份声明由账本自己读（它本来就持有执行器），扫描和账号读接口都从账本的同一处派生，调用方不用把天数传进来 |
| 令牌进来的时刻 | 账本版本 29 → 30 的 `account.credential_at` | 凡是写凭据的入口（登录窗口保存、重新登录替换、换密钥）在同一事务里记下时刻。这是凭据的事实，不是配置，也不从审计重放；升级前的账号这一列是空的，说“不知道”，不拿审计时间补 |
| 预计到期 | `shared/credential.ts` 的 `expectedExpiry` | 时刻 + 有效期，服务端和自检共用这一处。不知道时刻或没声明有效期就是 null。账本的 `accountExpiry` 把时刻和到期一起给页面 |
| 接口 | `service/http.ts` 的 `/api/accounts`（列表和单个） | 多给 `credential_at`、`expected_expiry`，不知道就是 null |
| 自检 | `service/doctor.ts` | 进入提醒期的账号一条“注意”，写账号名字和预计到期日，修法指向账号页；已过预计到期日的写“可能已经失效”。条目的 id 带上凭据时刻和状态（将到期 / 已过）：首页按 id 记住“不再提醒”，换了凭据或过了预计到期就是新的一条 |
| 主动推送 | `service/pushes.ts` 的 `account_expiry`（“等你”这一级） | 每个账号每份凭据只推一次进入提醒期，换了凭据重新计。提醒期只在入队时把关；提醒发出前按账本当前的行和执行器的声明重算“还在不在提醒期”，初发只核对“凭据还是当前那份”（窗口后来收窄不能让这份凭据一条都没推出去）。提醒和重复沿用推送表本来的做法 |
| 扫描时机 | `service/main.ts` 的推送定时器 | 用现有的那个计时器，不另造调度；窗口是设置项 `accounts.expiryRemindDays`（默认 30 天），由账本在应用它的事务里读 |
| 设置项 | `service/settings.ts` | `accounts.expiryRemindDays`（默认 30，1 到 365） |

**实现时定下的几处**

- “不知道”不是“没有”：`credential_at` 为空的账号既不显示预计到期，也不提醒，直到它的令牌再存一次。
- 提醒的窗口只在“进入提醒期”那一刻把关；已经入队的那条初发会照发（它进过提醒期，主人还没见过），此后的提醒按“还在不在提醒期”决定发不发。窗口收窄不会让一份凭据一条都推不出去。
- “在不在提醒期”只有一个判定（`insideWindow`），提醒按账本当前这一行和执行器现在声明的有效期重算，不信通知里冻结的到期日。
- “大约一年”是厂商的说法，`setup-token` 的令牌实际多久过期没有实测；这一版按 365 天估算，到期时的真实表现由第一次真实到期验证。
- 测试：`tests/account-expiry.test.ts`（时刻、预计到期、接口字段、每份凭据一次、换凭据重新计、提醒按当前行重算、初发只认凭据、29 → 30 迁移）、`tests/notify.test.ts`（通知的措辞与发不发）、`tests/doctor.test.ts`（自检那一条和它的 id）。

### 新账号的名字与删登录（2026-11-11）

一句话：新账号不用先起名字，名字由账本起；删一份登录会把它从项目的允许清单里去掉，并如实报出受影响的项目。

- 新账号可以不带名字：`POST /api/claude-logins` 新账号只发 `{ mode: 'new' }`，`POST /api/accounts` 不带 `name`。默认名规则只有一处（账本在建账号的同一事务里定名）：“<执行器> 账号”；和现存名字撞了就加序号（“x 2”），新建永远不因重名被拦。（原来按身份起名，邮箱优先、再组织；2026-11-12 起不再按身份起，见文末。）改名（`PUT /api/accounts/:id` 带 `name`）照旧拒绝重名。
- 登录窗口读到的组织随保存记进 `login_state`（`noteIdentity`），只用来认出同一组织的重复账号，不进名字。
- `LoginView.name`：新账号保存前是“此刻会用来保存的名字”（账本的默认名，一开始就有）；调用方传来的名字不读。保存后是账号的真实名字。
- 删账号、删机器自己的登录：同一事务里把它的编号从每个项目的 `logins_json` 里去掉，每个受影响的项目记一条 `project.update`（写明去掉的是哪份登录、按名字），删除的回答和删除前的确认预览都列出这些项目 id、名字和各自删后还剩几个可用登录。剩下几个由账本的 `loginPool` 推导：取删之前该项目的有效池，去掉这份登录后剩下的个数——项目切到“全部登录”时，清单只是留着、不参与派发，就不能说成“只允许用这个账号”。升级到 30 顺带清掉现存清单里已经悬空的编号（同样记审计，按 `account.delete` 的 `account.name`、`machine_login.delete` 的 `login_name` 或 `login.name` 反查原名，查不到写“已删除的登录”）。
- 项目的有效登录池为空（“只用所选”且所选都没了，或根本没有登录）时，账本的 `projectsWithoutLogins` 一处判定：`/api/overview` 的 `no_login` 给出这些项目（id、名字、原因），自检给一条“注意”指到那个项目的设置页。不按页面文字推断。
- 测试：`tests/account-name.test.ts`（默认名、重名加序号、删除清清单与审计）、`tests/account-expiry.test.ts`（29 → 30 迁移清悬空编号）、`tests/doctor.test.ts`、`tests/targets.test.ts`、`tests/logins.test.ts`。


### 账号页只有一个入口（2026-11-11）

主人看到账号页右上角并排着“添加账号”和“登录 Claude 账号”，问了两件事：为什么只有 Claude，为什么这两个是分开的。两个按钮本来就是同一件事（给 tycho 一份它保管的登录）的两种做法，第二节写的也是一个入口，这次按它收回来。

- 账号页只有“添加账号”。它打开一个窗口，依次问：哪个执行器、怎么登录；之后的步骤都在这同一个窗口里。名字不问（主人：每次让我起名字太烦，执行器本身就有用户名，想改事后编辑就行）：新账号由服务起名（“<执行器> 账号”，2026-11-12 起不再按身份起，见文末），重名自动区分，窗口在授权成功后写一句“账号会叫 X”；改名在账号的抽屉里。控制台建账号的两个请求都不带名字。
- 执行器一栏列出主机认识的全部执行器。声明了取得登录的方式的（现在只有 Claude）可以选；其余的照样列出、选不了，并写明“它的登录留在机器上，tycho 不保管”，下面一句话指到机器页。“为什么只有 Claude”在这里回答，不靠文档。
- 怎么登录由执行器自己声明：适配器的 `accountLogin` 按提供的先后列出方式（词表在 `shared/logins.ts` 的 `ACCOUNT_LOGIN_WAYS`，现在是 `page` 在官方页面授权、`key` 填 API 密钥、`provider` 选线路填密钥、`machine` 在一台机器上登录），只对声明了 `credential` 的执行器有意义。`/api/accounts` 的 `account_logins` 按执行器给出这些方式，各带“这台主机现在能不能做”和做不了的原因（官方页面授权是主机上的一次登录会话：只对登录会话服务的那个执行器可用，还要主机上有登录助手）；原来的 `claude_login` 一项删掉了。窗口照这份清单画：默认选第一个能做的，不止一种时把第一种标成推荐，做不了的选不了并写明原因。贴令牌那一条当时留成同一个窗口里的次要做法，2026-11-11 曾计划删掉，后来删掉了（见本文末“贴令牌的入口已删”）。
- 选官方授权：点“开始登录”后就是原来的登录步骤，登录成功、模型读完（或读不到）后直接出现档位表单，不再多点一次“填档位”。
- 窗口和账号页不认执行器的名字，只读 `account_logins`；账号卡上的“重新登录”看这个执行器有没有声明 `page`。以后 Codex 的设备码登录（第 4 步）、dsh 的 provider 账号（第 2 步）落地时，是词表里多一个方式、适配器多一条声明、窗口里（`console/src/components/add-account.tsx` 的 `WAYS` 和它下面的步骤）多一段，不再加并列的入口。
- 登录会话和它的接口没动。

Codex 和 dsh 现在仍然不能在这里登录，原因没变（第一节）：Codex 的登录会轮换、只能留在机器上，要等第 4 步在那台机器上发起设备码登录；dsh 要等第 2 步的 provider 账号。在那之前它们是机器自己的登录：机器报告已登录后自动成为登录，带好默认档位，想换模型到账号页或机器页改。

控制台在 `console/src/components/add-account.tsx`；测试在 `console/src/components/claude-login.test.tsx`、`console/src/pages/accounts.test.tsx` 和浏览器冒烟里两条（填 API 密钥、官方授权）。

### Codex 和 dsh 的账号：实测后的定稿（2026-11-11）

主人看到“添加账号”里只有 Claude 能选，要求把另外两家补上。动手前在本机实测了第一节里“还没验证”的几条，结论比原稿多出一种账号，分步也跟着重排。

**结论：三家都能在“添加账号”里加，一共四种登录。**

| 执行器 | 怎么登 | 登录放在哪 | 哪些机器能用 |
|---|---|---|---|
| Claude | 官方页面授权 | tycho 保管 | 项目放行的每台机器 |
| dsh | 选一条线路（DeepSeek 官方，或自定义的地址、协议和模型），填它的密钥 | tycho 保管 | 项目放行的每台机器（要够得着那个地址） |
| Codex | 填 API 密钥 | tycho 保管 | 项目放行的每台机器 |
| Codex | 选一台在线的机器，用设备码登录 ChatGPT 订阅 | 那台机器上 Codex 自己的目录 | 那台机器（和它共用 Home 的机器） |

**实测到的事实**（实录在 `tests/fixtures/dsh/0.2.2-rc.1/line/`、`tests/fixtures/codex/0.162.0/api-key/`、`tests/fixtures/codex/0.162.0/login-device/`）：

- dsh：headless 档默认关着存凭据的三个服务，这时线路的密钥直接取启动环境。自定义线路读它 `apiKeyEnv` 指的变量，官方线路读 `DEEPSEEK_API_KEY`。输出和 `DSH_HOME` 里都不留密钥。第六节那一行“这条线路必须开凭据服务”的退路用不上。
- Codex：`codex exec` 从启动环境的 `CODEX_API_KEY` 取密钥，而且压过机器上已有的 ChatGPT 登录。所以 Codex 也有一种能搬运的登录，原稿第一节“Codex 做不到”只对 ChatGPT 订阅登录成立。
- Codex 的设备码登录（`codex login --device-auth`）打印一个固定网址和一个一次性用户码，15 分钟有效，登录成功以退出码 0 结束。
- Codex 另有一种访问令牌（`CODEX_ACCESS_TOKEN`，ChatGPT Business 和 Enterprise 工作区才能建）。本机的 0.162.0 对假值和没给一样，没有可用的实测，这次不做。

**和原稿不同的几处**

- **Codex 多一种 API 密钥账号。** 它和 Claude 账号是同一种东西：tycho 保管一段密钥，每轮交给那一轮。设备码登录照原稿做，结果仍是那台机器自己的登录。
- **凭据怎么交给一轮，由适配器声明**（`Adapter.credential`）：启动环境里的一个变量。“能不能当账号”就看有没有这条声明，不再另列名单。经环境交付时，Worker 起的子进程会继承这个变量；这是执行器自己读密钥的方式决定的，边界仍是机器。文件描述符那条路已经删掉：Windows 上 claude.exe 2.1.303 不读它（实测见 [../spike/claude-credential-way.md](../spike/claude-credential-way.md)），会悄悄用机器自己的登录跑。适配器还可以声明一条不耗额度的问法（`Adapter.credentialCheck`），让机器在上报执行器时核实交过去的令牌会被采用；报了不会采用或没报的机器不接这个执行器的账号的活，机器自己的登录不受影响。
- **dsh 的密钥变量看线路。** 自定义线路用 tycho 自己的变量 `TYCHO_DSH_API_KEY`；官方线路用 dsh 的默认变量 `DEEPSEEK_API_KEY`，这样 dsh 自带的联网搜索照常能用。自定义线路不用后者：dsh 的联网搜索会把它发给 DeepSeek。
- **线路不拼进档位，单独成一个文件。** 账本在账号上多存一份线路定义（不含密钥，账本版本 28）。派发时适配器把它写成一份 patch，作为快照里的 `line.patch.yml`，启动命令先给档位、再给线路：dsh 按顺序叠 `--patch`、同一条目以最后一次为准、`config` 整块替换，所以档位改不动线路。这份 patch 同时显式关掉存凭据的三个服务，机器上存着的旧密钥不会抢在前面；官方线路还写明自己的密钥变量和地址，机器环境里的 `DEEPSEEK_BASE_URL` 指到别处也不影响（实测）。档位里的 provider 必须是这个账号自己的线路，碰了这三个服务和线路定义的档位在保存时被拒并说明（只是提示，保证靠 patch 的先后）。会话不跨线路续接。
- **自定义线路的表单**：地址、协议、模型清单、密钥。每个模型填名字、它接受的推理强度、能不能看图。重试、兼容开关这类设置放在“线路的其他设置”里，按 dsh 自己的写法原样保留。线路在 dsh 里的名字固定是 `tycho`，显示名用账号的名字，不另外问。
- **模型清单可以从线路读回来。** 表单上的“从线路读取”由主机直接去问那条线路（`GET <地址>/models`，带上刚填的密钥），顺带验证地址和密钥。主机够不着的内网地址就手填。原稿里“在某台机器上测试连接”的那条封闭命令不做。
- **输出隐去密钥放在 Runner 读输出的入口**（`runner/redact.ts`）。实时事件、结算时读的结果、事后读回的历史都经过它，对三家一视同仁。机器上的原始日志不动。
- **机器登录仍按“每台机器、每个执行器一份”记**，原稿第 3 步（挂到 Home 上）这次不做。影响：在一台机器上重登 Codex 时，只检查这台机器上在跑的轮次；共用 Home 的另一台机器上的轮次查不到。
- **节点协议升到第 5 版，只升这一次**：凭据可以经启动环境交付；多两条封闭命令（开始、取消机器上的登录）；poll 带上登录进度，主机在回答里列出它还记着的登录，机器据此收场。

- 真实的 DeepSeek 官方接口没有跑过（替身网关不会说它的流式格式），只确认了密钥从哪个变量取、走哪个请求头。

### 贴令牌的入口已删（2026-11-11）

主人用登录窗口真实加过 Claude 账号，验收通过，第五节排的删除做完了。Claude 的登录现在只有一条进来的路：在官方页面授权。

- 词表 `ACCOUNT_LOGIN_WAYS` 是 `page`、`key`、`provider`、`machine`，没有 `token`；Claude 适配器声明 `accountLogin: ['page']`。`takesTypedLogin` 只认“自己填密钥”的 `key`、`provider`，`service/http.ts` 在新建账号（`POST /api/accounts`、`PUT /api/accounts/:id` 带 `credential`）和直接换凭据（`PUT /api/accounts/:id/credential`）两条路上按它拒收其余执行器（`typedLoginRefusal`）。拒的是接口边界而不是 `accounts.put`：登录窗口写同一份账号走的是同一个存储。编辑账号的档位、限额照旧；Codex 的 API 密钥和 dsh 的线路密钥不受影响。
- 控制台：“添加账号”里 Claude 只剩“在官方页面授权”一种；账号卡按这份登录是怎么来的说话（文字只在 `shared/labels.ts` 的 `credentialText`）：自己填的密钥写“API 密钥 已设置 / 已失效，要重新填”，“更多”里有“更换 API 密钥”；在官方页面取得的写“登录 已登录 / 已失效，要重新登录”，没有“更换”这一项，只有“重新登录”。
- 告诉主人怎么办的几句话一起改了：登录失效的推送、任务等登录的说明、总控停摆的修法，原来都写“重新填登录令牌”，现在写“到账号页重新登录或换密钥”（`ACCOUNT_LOGIN_FIX`）或“到账号页给它点重新登录”。
- 非 Windows 主机上官方页面授权做不了（登录助手只在 Windows 上有），这时 Claude 没有任何能做的方式，窗口里那一项选不了并写明原因。这是删掉贴令牌的代价，主人的主机是 Windows；别的主机要用得先做那边的登录助手。

**独立审阅后改的**（2026-11-11）：读线路模型的接口不再接受“用某个账号已存的密钥去问”，已存的密钥只会随它自己的线路发出去；关窗口时还没回来的“开始登录”在答复一到就取消；机器在动手前就说不开工（例如取不到这一轮的凭据），这一轮按“没有开工”结束并写明原话，不再被当成开工过又丢了；凭据为空和没给一样，这一轮不开工；取消和登录成功同时发生时记成已登录。

### Claude 登录令牌读不到账号是谁（2026-11-12）

一句话：在官方页面授权拿到的 Claude 令牌只有调用模型的权限，读不到邮箱或用户名；新账号因此叫“claude 账号”（重名加序号），建好后在账号抽屉里改名。新账号一建好就读一次额度。

起因：主人加第二个 Claude 账号，账号名成了一串组织编号，账号页也没有 7 天窗口。

- 实测（两个真实账号）：`claude setup-token` 申请的权限只有 `user:inference`。用它问 `/api/oauth/profile`、`/api/oauth/account`、`/api/oauth/usage` 都回 403“OAuth token does not meet scope requirement user:profile”；CLI 自己在这一步也不打印、不保存账号的邮箱。能读到的只有模型清单回答头里的组织编号。所以“用执行器自己的用户名起名”对这种登录做不到，原来的资料请求从来没成功过。
- 改成：删掉资料请求（适配器的 `accountProfile`、`readModels` 的 `profile`），执行器身份只剩组织编号（`ExecutorIdentity`），账本读写都只留这一项；组织编号不是名字，默认名只看主人写的名字或“<执行器> 账号”。账号的组织编号照旧用来认出重复账号。窗口在授权成功后照旧写“账号会叫 X，建好后可以随时改名”。
- 额度：读额度原来只在“用量”页打开时对过期的读数做，新账号建好后账号页一直空着。现在账号一建好（登录窗口保存、直接建账号两条路）就按同一条规则（`quota.readStaleMs`，0 时也不问）问一次，不等结果；读到后账号页照常刷新。改账号不触发。
- 主人那份已建好的账号：主人已手动改名；它的额度已读到。
