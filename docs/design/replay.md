# 查看录制现场与隔离评测待验收规则

任务页提供两种独立操作。录制事件回放逐条展示已保存的现场，不重新执行任务。隔离规则评测用冻结输入比较待验收规则，不调用模型，也不向真实渠道发消息。正常任务现场仍表示实际发生过的事实。

## 在控制台查看与评测

以主人身份打开任务页，展开「回放与隔离重跑」。选择轮次后读取录制事件，再用下一条、播放或进度条查看。界面显示读取时间、已录制条数及缺口；它只播放此次读取的事件，裁剪或过期的正文不会凭空补齐。

同一面板的隔离评测提供冻结案例和 tune/release 分组。核对输入及独立期望后手动运行一次。结果列出源码摘要、两边的业务状态、通知和交给总控的规则回合数，并检查外部副作用为零。这里的回合数是规则是否交给总控的判定，不是实际模型调用次数。服务端只接受规定的案例结构，不能填入任意代码或源码目录。

从当前轮次生成的草稿只导出脱敏结构事实。补齐草稿列出的历史事实并独立填写期望，才能制成评测案例；草稿本身不能直接运行。控制台和下述 CLI 共用同一规则实现。

工作区里的回放命令用同一组冻结案例运行两版待验收规则。当前基线关闭「验证报告直接通知」，候选开启。每边从空的临时账本开始，通过真实的结算、出站队列和通知渲染执行，发送端只把企微目标及消息写进内存。

## 复跑发布验证

在 Tycho 源码目录运行。用默认发布集核对首轮，还可以用 `--split tune` 跑较早的调优集。两组的案例身份由 `case_id`、任务族和日期固定。可用 `--baseline` 和 `--candidate` 指定两个本地源码目录。命令会加载目录里的代码，选择你信任的检出。

```sh
node scripts/replay.ts run --split release
node scripts/replay.ts run --split tune
```

结果逐案比较业务状态、审批、总控验收权限、回执、产物与轮次绑定，以及实际交给假传输的通知内容、顺序和收件人。结果列出首次结算和一次重复结算之后总控会收到的消息。独立判定有任何失败则退出码为 1。当前八个演示案例覆盖台账旧任务、业主明确验收、总控有权验收、并行工作、未处理请求、订阅和关闭企微。

## 从历史案件制作为验证场景

用能读取 Tycho 备份的身份运行导出。指定已结算的验证轮次、案例集和新建文件名。导出留结构事实与散列后的轮次标识，账本中的消息、正文、报告路径、账号和凭据不进入文件。

```sh
node scripts/replay.ts export --ledger <ledger.db> --run <轮次编号> --split release --out <草稿.json>
```

草稿的 `missing` 提示需要审核的事实。核对结算前的权限、频道、并行工作与订阅，选定或者扩充符合事实的脱敏输入，并独立写出期望结果。按 [案例定义](../../scripts/replay-ready-notice.ts) 去掉草稿字段，填写 `inputs` 与 `expected`，用 `node scripts/replay.ts run --case <定稿.json>` 检查。真实模型和外部工具的输出只能用固定替身复现。历史账本未记下的工具调用、原生配置或第三方状态需要另行核实。
