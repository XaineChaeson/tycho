# 用量与额度

读者：改用量记录、额度读取或“用量”页的人（含 Agent）。回答的问题：每一轮用掉了多少从哪来、记在哪、页面怎么算；账号还剩多少额度怎么读、多久读一次。

## 一句话

用量由执行器自己报，适配器把它规范成一种形状，在产生它的地方记进账本一次：Worker 每轮在结算的事务里记，总控每回合在结果行到达时记，问额度那一次也记。统计页只做查询和聚合，不另存汇总；执行器没报的就写没有，不估算。额度是执行器报的窗口读数，和用量是两回事：它记在登录的 `login_state` 里，账号页、挑登录和“用量”页读的是同一份。

## 1. 每轮的用量从哪来

适配器的 `Usage` 是一个模型的四个数（输入、输出、缓存读、缓存写）加可选的模型名和标价金额。四个数互不重叠：输入只算既不是缓存读也不是缓存写的那部分，不管执行器自己怎么数。

| 执行器 | 报什么 | 规范时做的事 |
|---|---|---|
| Claude | 结果行里 `model_usage_since_last_result`：按模型的四个数和 `costUSD`（`costBasis: "list"`） | 只取这一项：累计的 `modelUsage` 在续接的一轮里含着之前几轮（2.1.309 实录），会重复计。标价只在 `costBasis` 是 `list` 时收；没有这一项的旧版本（2.1.303 实录）退回顶层 `usage`（这一回合主线程的数），不带价，模型只在累计的 `modelUsage` 只有一个模型时取它的名字 |
| Codex | `turn.completed.usage`：输入里含着缓存读（0.163.0 实录 15104 里 12160 是缓存） | 输入减去缓存读。不报模型、不报价 |
| dsh | 每步 `step_end` 的 `usage`，输入不含缓存（实录 256 + 39 + 7168 = 7463） | 按步相加。不报模型、不报价 |

执行器没说模型的，记这一轮档位里写的模型，`model_basis` 标 `tier`（页面写“按档位”）；档位也没写就是空，页面写“执行器没说是哪个模型”。

标价是执行器按 API 标价折算的数，不是账单：订阅账号不按它付钱，只能当“相对用了多少”看。只有 Claude 报，所以金额的合计只算报了的记录，页面在没报的行上写“无数据”或打星号。

## 2. 记在哪

账本的 `usage` 表（账本版本 27），一行是一个模型的用量，`run_id`、`context_id`、`login_id` 三者恰有一个，说这是谁用的：

- Worker 的一轮：`settleRun` 在结算的同一个事务里写，时刻就是这一轮的 `ended_at`。重复结算不写；只有一种例外：这一轮先按丢失结算、当时没有用量，机器连回来后真正的结果带着用量到了，就按它的 `ended_at` 补记一次。没开工、也没报用量的轮次不算一轮。
- 总控的回合：每个结果行到达时写，挂在这个执行器上下文上；一个结果行是一个回合。
- 额度查询：挂在被问的账号上（§3）。

项目、职能、登录、执行器都不另存：查询时从轮次（`run` 和它的快照、任务）和上下文推出。改过名的登录和职能显示现在的名字，删掉的显示当时的名字。

## 3. 额度怎么读

执行器在每次请求里顺带报账号的窗口（Claude 的 `rate_limit_event`：5 小时、7 天等，用了多少、几点重置）。tycho 用这个账号跑一轮或总控回合时就记下（`noteUsage`），不花额外的额度。只靠这个有两个缺口：账号闲着时数字停住，在 tycho 以外用掉的看不到。

所以主机可以主动去问：适配器的 `quotaRead` 声明 HTTP 地址、头、body，以及额度头和响应用量的解析。tycho 保管的 Claude 账号直接 `POST https://api.anthropic.com/v1/messages`，带账号的 Bearer 令牌、`anthropic-beta: oauth-2025-04-20`、`anthropic-version: 2023-06-01`，请求 `max_tokens: 1`，系统说明是 `You are Claude Code, Anthropic's official CLI for Claude.`，用户消息是 `1`。服务不启动 CLI、不读取主机的执行器配置，出网复用模型查询的全局 `fetch` 和启动时的代理配置。

模型取账号已有模型列表的首项，不读档位、不写死型号：列表由现有 `listModels` 解析，没有价格或大小字段，tycho 不另维护价格表，也不声称这一项最便宜。列表为空时先经现有模型刷新入口查询（有它自己的时限和并发去重）；仍为空或查询失败就报告原因，不发推理请求。

响应头每个 `anthropic-ratelimit-unified-<窗口>-utilization` 各记一项，`-reset` 的 Unix 秒转成重置时刻；`5h` 规范成 `five_hour`，`7d` 规范成 `seven_day`，`7d_oi` 和 `seven_day_overage_included` 规范为 `seven_day_fable`（Fable 周额度），其他窗口保留名称（连字符转下划线），不补没报的窗口。CLI 事件也采用同一窗口名；读取旧账本时将这些别名合并，取最新读数，不改写旧数据。读数照常记进 `login_state`；响应 body 报的四类 token 记作“额度查询”，没有标价就不估算。即使没有额度头，已报告的请求用量也照记。

2026-11-12 用 setup-token 实测：`GET /api/oauth/usage` 缺 `user:profile` 权限而回 403（也遇到过 429）；`POST /v1/messages/count_tokens` 回 200 但无额度头；上述最小消息请求回 200 并报 7 天窗口，当时没有 5 小时窗口。主动查询仍花一点额度，这一点在按钮和设置说明里写明。

- 打开“用量”页时，读数比 `quota.readStaleMs`（默认 10 分钟，0 是只手动）旧、而且这段时间里也没问过的账号，各问一次，不等结果。新建好的账号按同一条规则马上问一次，账号页不用等用量页打开才有窗口。
- 页首“刷新额度”问每行有读法的订阅或登录，每行旁的“刷新”只选这一行。两种 `POST` 都立即返回当前页面数据，随后由页面重新 `GET` 取结果。同一订阅选一个来源，优先选可读的在线机器。同一台机器收到一次重看请求。
- `quota.readTimeoutMs` 只约束额度 HTTP 请求（含读取 body），到时中止连接。问不到（超时、没有额度头等）就保留上次的数，页面写“几点没问到：原因”；HTTP 失败保留状态码和服务返回的错误类型，原因里的令牌一律隐去。
- HTTP 401 记在被拒的那份凭据引用上（`rejectCredential`，和总控路由拒用同一套判定）：这份登录停止自动重读、账号页和用量页写“需要重新登录”，主人换过凭据后恢复。在途的 401 只拒它出发时用的那一份：换过之后到不了新凭据上。HTTP 429 且响应里带着能用的窗口，算一次成功的读数——窗口和这次花掉的 token 照记，窗口用满时页面写“额度已用完”；429 且一个窗口都没有，不算失败：按响应里的 `Retry-After`（没有就默认 60 秒，最多 30 分钟）抑制重试，页面中性写“临时限制了这次读取”，上次的数字留着。单凭一个普通 429 不改派发。
- 机器自己的登录凭据在那台机器上，主机问不了，所以由那台机器的客户端在本机读，随执行器报告上报（`Adapter.machineQuota`，[nodes.md](nodes.md) §1.2）：Claude 是跑一条不跑推理的命令读 `/usage` 的窗口行（实测 55 秒，时限 `node.quotaReadTimeoutMs` 默认 120 秒），Codex 是在 `app-server` 上按行问一次 `account/rateLimits/read`（实测 4 秒）。这一读跟着机器看执行器的时钟走、在报告旁边（不挡报告），主机收到后写进那份登录的 `login_state`（和别的读数同一处、同一形状，按机器读到的时刻判新旧）。页面给读数、读到的时刻和上次没读到的原因；“刷新”就是让那台机器现在看一次。执行器不声明读法（dsh）就写“这个执行器不提供用量”。命令没跑成或回答读不出来是失败（红色照写）；一份有效回答却没有窗口行（订阅说明里没带窗口行）是 `absent`：不写窗口、也不算失败，页面中性写“这次没有读到额度窗口”，上次的数字留着。
- 客户端复用已有的 `claude auth status` 探针。当登录方式为 `claude.ai`、订阅为 `pro` 或 `max`，且组织编号符合 UUID 格式时，客户端上报归一为小写的编号。主机核对编号并写入机器登录的 `login_state`。登录探针还可上报仅供展示的邮箱用户名，订阅匹配仍只看组织编号。探针确认组织变更或已无可识别的个人订阅时，主机清除原匹配及该机器登录的旧额度。额度命令若在身份变更前启动，客户端丢弃它随后返回的结果。

机器读数也在适配器解析入口统一窗口名：Claude 的 `Current session` 是 `five_hour`，`Current week (all models)` 是 `seven_day`，按模型的周窗口是 `seven_day_<模型名小写>`；Codex 按 `windowDurationMins` 将 300、10080 分别记为 `five_hour`、`seven_day`，其余记为 `<分钟数>m`，非 `codex` 桶在前面加 `<limitId>_`。

## 4. “用量”页

一页两段，一个刷新入口。

- **剩余额度**显示窗口、用量、重置时刻和读取时刻。机器自己的登录确认了个人订阅，且与已登记账号的执行器、组织编号都一致时，用账号名称显示一行，注明同一订阅的其他登录，展示其中最近一次有效的窗口读数。其他登录各自一行。账号页仍可单独更换凭据。数据来自 `GET /api/quota`，刷新调用 `POST /api/quota/refresh`。空请求只读过期的已登记账号，`all` 刷新全部，`login_id` 刷新一行。
- **消耗**：时间范围（7、30、90 天，按读者的日子切），按项目、模型、职能、档位、账号分，看 token 或标价折算。数据是 `GET /api/usage?from&to&tz`，服务按日子和各维度汇总成格子，页面再按选的维度相加。总控的回合算在它的项目里，职能和档位两栏单列“总控”；职能和档位是这一轮快照里记的，改任务的职能只影响以后的轮次；额度查询在项目一栏单列。项目删掉后剩下的用量行在项目一栏单列“已删除的项目”，数字、日子、登录和计量单元都留着（`usage.dropped_source` / `dropped_unit`），不和额度查询混在一起：删项目不改用量总数、轮数和时长，也不把一轮算成零轮。一轮用了两个模型，按模型看时两边各算一次，合计里只算一次。没有用量数据的轮次照样计数，并写明有几轮——删掉的项目也一样：那一刻的时长写进用量行的 `duration_ms`，没报过用量的一轮为它留一行只有计量单元、时长、没有模型、四个数都是空的 `usage` 行，它仍算一轮、仍算没报用量，只是不进按模型看的那张表。

参照过的做法：Anthropic、OpenAI 控制台的 usage 页（按天分桶、选一个维度分组、四类 token 分开），Langfuse（执行器报的优先，不报就不推算；OpenAI 系“输入含缓存”的重复计数），LiteLLM、Langfuse（每次请求一行明细，汇总在查询时做），ccusage 和 Claude Code 自己的分析（订阅用户看 token 和“标价估算”，明说是估算），Helicone（最耗用量的功能）。没取的：价目表推算（要长期维护，订阅账号的推算会冒充花费）、预算和告警。

账号页也按用量页相同的身份规则展示：只有机器确认的个人订阅组织与同执行器的登录匹配时才成组。组名优先采用 tycho 保管账号的名字，共用额度只显示一次，展开可分别管理各登录；不同组织或身份未知的登录仍各自显示。分组只影响展示，不改变凭据或派发顺序。
