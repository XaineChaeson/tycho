# 项目交接时保留知识和文件

面向将办公项目移到家庭服务的使用者：目标服务应能读回已完成任务的原报告、当时的知识修订和登记文件，并用当前项目知识做下一件工作。沿用现有 export → stage → freeze → import，不建立持续同步服务。

状态：知识与普通登记文件已完成公开接口回归；真实 Windows 774 Worker 已读取知识 @1、交付并登记 256 KiB 文件，Console 更新 @2 后旧快照不变。Worker 主动提出经验并通过独立把关后，原导出明确拒绝其服务级把关历史，尚未冻结或完成物理移交。现在补齐这个实际消费者的已终结把关闭包，之后仍须走同一项目的完整物理交接与目标下一轮验证。

## 知识的当前归属与历史分开处理

知识模块决定一条知识的当前头、历史、提议和证据依赖。第一份样条使用真实 Console 发布、当前头仅归一个项目的知识，保留同 ID 的 @1、@2、当前头和完整提议证据。当前头仅归本项目、旧修订曾是 global，不据此改写或丢弃旧 scope；必须先核实历史复制授权与引用闭包。当前头为 global 或由多个项目共享时，不能作为本项目资产导入后自动在目标全局生效。

第一步保留所选知识 ID 的完整、获准历史，维持已有修订列表语义。所需历史或其依赖不能移交时，指出对象和原因，暂不引入部分历史标记。全历史是为维持这个公开接口作出的选择，不是说未引用版本都是算法必需。不得重新 propose 成新 ID、改旧 revision scope 或搬走无关项目来满足 FK。

Worker／总控提议引用的知识把关 Task 保持 `project_id=null`。只携带由所选提议精确推导、原来已经 done 或 abandoned 的 gate 及全部结束 Run、快照、报告、输入和审计；不能按空项目字段把所有服务级工作抓进来。Worker 来源必须回到原 Task／Run 的项目；总控来源必须有持久知识调用与项目因果，旧记录无法证明时拒绝。提议的原 change 和把关后的 final 分别保留，不能把原来建议的全局范围误当作最终发布范围。

旧修订含其他项目、全局或共享当前头、在途把关、无确切来源及不支持的知识工作仍明确拒绝。gate 快照只识别既有知识材料生产者的结构，保留完整原字符串并核对所需条目修订，不重渲染旧材料。失败历史从未产生正式报告时保持原缺失；已经存在的正式报告不能在迁移时丢掉。

这些是切点历史，不是迁移服务级执行权。既有终态规则拒绝改定义、恢复执行或重新采用结论，不另建档案实体或归属守卫。源服务后续可能记录迟到观察、恢复原本缺失的报告或执行保留清理；这些维护元数据不持续同步或覆盖目标收讫的历史。项目总控的服务级 Task／Run 读取边界不因迁入而放宽，目标 Owner 沿原有服务规则查看。项目当前知识仍由归属服务按 generation 单写。共享当前头需要独立的发布物与授权设计，不在本包偷用可写全局行代替。

Owner 对选定项目及内容的移交负责。外部 URL、Git 或文件证据只携带已经核实并获准的摘录及其原事实，不为导出重新访问外部来源，不复制 token 或授予目标新的外部系统访问权。Opaque 正文和文件的授权不能靠关键词扫描代替。

目标准备时同时核对提议 ID 与知识模块的非空 `(client_id, request_id)` 唯一身份，冲突先于源冻结暴露，不重写历史请求号。本版是离线交接；准备只核对当时的目标状态，不是全局键保留或跨服务事务。窗口中目标又被写入时，接管仍会复查并明确拒绝；这不会自动解冻来源。保留原包和凭证，由 Owner 核实，不把换请求号或另选目标当作冻结后的自动恢复。

## 格式在入口归一

新增 v2 JSON 包，保留现有 Buffer 和 Owner-only CLI 文件入口。新导出默认使用 v2；新读取器继续接受真实 v1 包，归一为空新增闭包。冻结源按输入包的原格式重新导出并比较完整字节摘要，避免新默认格式使旧 v1 交接无法继续。不增加第二套用户导出命令或通用同步器。

v2 包含原有行、经知识模块核定的知识闭包，以及由原 Registration 推导的文件清单。文件只有 run ID、registration ID、正常文件名、字节数、SHA 和内容，不接受自由目标路径。原 snapshot、报告和审阅绑定保持原样。整个编码 JSON 继续受现有 64 MiB 上限约束，base64 膨胀计入；这不是 Console 的 UTF-8／128 KiB 预览预算。超过预算明确报告，不省文件凑通过。真实大包需求出现后再评估流式容器。

## 文件先准备，账本后可见，归属最后切换

产物模块从已经登记的不可变目录读取文件，复用 Registration、BoundFile、文件名和摘要规则。历史审阅引用的旧登记从已有审计中恢复清单，不遍历目录猜产物。已清理的事实继续保留；所需文件丢失、大小或摘要不符就停止导出。受管根按配置解析，根以下拒绝链接和特殊文件，打开文件后再核对大小与摘要。

回执声明有文件、却没有可携带的登记材料时，在源冻结前明确拒绝，报出 Run 及登记前置；不凭回执路径猜读文件。已有清理事实仍按原样移交。正常取回可以补齐仍可访问的材料；从未登记且原节点永久不可达的历史，目前不能标为不可用后继续迁移。这是现有产品缺口，后续真实消费者出现时由产物模块决定其事实与 Owner 确认入口，不用本次导出偷偷忽略。

目标先在自己创建的私有 incoming 中验证全部文件，再排他安放到原 run／registration 位置。已有路径只有在同一交接、同清单和所有字节完全一致时才视为重试；未知目录或冲突不覆盖。随后用一个账本事务安装知识、任务和交接标记，最后沿原流程切换 authority。文件系统、ledger 和 authority 不承诺物理原子事务，依靠同收据和完整内容核对恢复。旧账本恢复不得回退 authority 的冻结事实。

## 样条的通过条件

一个无在途副作用的非空项目，包含结束任务、正式报告、项目知识 @1／@2 和至少一个实际登记普通文件，先在当前公开交接入口复现拒绝，再通过同一入口移交。目标读回稳定 ID、原修订、快照、报告、审阅引用及文件摘要，用 @2 创建下一件工作；原 @1 仍可查。保留 v1 导入与冻结、他项目／全局头越界、文件链接／冲突／丢失及各提交故障点的拒绝或恢复证据。

Owner 的小项目移交是新增保证的消费者；成本是有界包、引用及权限核验和三域恢复。凭据、机器原生会话、在途外部副作用不在此保证内。单一交接 owner 维护解析、安装和 authority 整合；知识与产物模块分别拥有自己的语义和文件事实。接口未冻结前不拆分多个实现者修改交接核心。
